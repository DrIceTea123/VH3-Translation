# 现行规则

归并日期：2026-10-01。来源为用户明确要求及已接受方案；历史依据见 [已归并记录](README.md)。

## 协作与文件

- 需求不清晰或需要决策时先提问，说明原因；不得擅自设定。新内容放置在合适位置。
- 仅用户明确要求时提交 Git；开发、修复、初始化、整理不包含提交授权。
- Git 管理当前工程和维护文档。主工程是 `program/`；原始输入、旧译文、公告、表格、checker、工具、发布成品留在父目录。
- 原始输入保持原样；不记录用户提供的原始整合包实例路径，可记录版本和有用的模组信息。
- PowerShell 使用 `-LiteralPath` 访问方括号路径。保留安装脚本既有编码；OpenLoader ZIP 是安装输入，不统一忽略或删除。
- 持续维护本项目共享记忆，记录决定、事实、验证和待办变化；不修改全局记忆。TODO 不自动授权执行。

## 补丁与翻译

- 针对固定 the_vault 版本渐进接管，保留其他 VP 翻译；开发时分析字节码，运行时不反编译/编译 Java，不重建整个上游 mod。
- 在显示边界翻译，保留业务 ID、存档键、网络字段、XP 与统计逻辑。客户端 I18n 不进入专用服务端路径。
- 每个功能模块各有运行侧和转换侧模块类；名称处理、导入、VP 判定留在对应模块，通用 JSON、重载、ASM 校验共享。源码适当添加中文注释。
- 模块配置只作用于所属模块，不按语言拆分、不覆盖全局语言键。文件名由模块 ID 决定。
- `combat_stats.json` 使用实体路径（如 aggressive_cow）；`sound_names.json` 使用原始字段名（如 RAFFLE_SFX）；其他模块默认英文到中文，特殊输入先确认。
- 映射只维护在 `program/基础+硬编码汉化/config/vh3_translation_patch/`，源码与导出 JAR 不保留配置副本。新增现有模块条目只改 JSON。
- 首次配置缺失或损坏阻止启动并提示修复；F3+T 失败保留上次有效配置。声音名重载后重新打开声音设置生效。
- 精确核心哈希、目标方法签名/摘要/命中数、配套版本或 VP 冲突不匹配时阻止启动，不静默禁用。保持战斗牛与首领差异；未知 ID 不得误取注册表默认实体。
- 移除被 VTP 接管的 VP 规则，在原位置留注释说明内容及接管模块。VP 长列表阈值、local/ordinal 与关联规则统一见 [分类规则](../docs/maintenance/vp-asm-layout.md)。

## 版本与交付

- mod 使用 `1.x.x`，首版 1.0.1。普通修改修订号 +1；the_vault 更新时小版本号和修订号均 +1，例如 `1.0.3 → 1.1.4`，修订号始终不重置。同轮构建重试不重复加号。
- 每轮 mod 修改后完成验证并导出两个同版本 JAR 到 `program/基础+硬编码汉化/mods/`，只清理本补丁旧 JAR，不清空 mods。
- 工程 mods 中的两个 VTP 配套 JAR 作为安装输入纳入 Git；忽略规则按版本通配放行这两种文件名。其他 JAR 与构建目录继续忽略，提交仍需用户明确要求。
- 构建、离线字节码验证和游戏验收分别报告；没有执行不得声称通过。源码与 JSON 使用 UTF-8，不对 Windows JDK 17 的 Gradle 启动器强设 UTF-8 参数文件编码。
