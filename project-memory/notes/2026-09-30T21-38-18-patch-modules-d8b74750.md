## 用户确认的配置约定

- 每个接管内容独立成模块，放入专门的软件包，以模块类组织，便于后续添加。
- **只有结算怪物名称模块按原始标识查表**；配置使用 `"aggressive_cow": "战斗牛"`，不采用助手最初建议的 `entity.…` 键。
- 其他模块默认使用英文原文到中文的映射，例如 `"Aggressive Cow": "战斗牛"`。
- 每模块一个文件，当前为游戏目录下 `config/vh3_translation_patch/combat_stats.json`；文件名由模块中的 `combat_stats` ID 决定，不按语言拆分。
- 配置只作用于所属模块，不覆盖全局同名语言键。
- 首次生成，后续不覆盖已有文件；支持 F3+T 重载，错误时保留上次有效配置。
- 源码中适当添加中文注释。用户未要求提交，本轮不暂存、提交或推送。

## 实现

- 运行侧 `com.dricetea.vh3patch.modules.CombatStatsModule` 负责结算名称；`TranslationModule` 默认保留输入文本原样作为键，结算模块重写为取冒号后的实体路径。
- 早期侧 `com.dricetea.vh3patch.transformer.modules.CombatStatsModule` 声明目标、运行侧入口及 VP 冲突常量。两层保留各自的模块类和不同 Java 包，不跨加载层引用类型。
- `PatchModule/PatchModules` 注册并按目标类组织变换；启动检查和离线工具共用注册表。通用 `StringReturnPatch` 保留原算法与校验，只适用于实例 `(String)String` 方法。
- 方法清单迁到 `transformer/src/main/resources/patches/combat_stats.properties`；只接管原先的一个结算方法，仍有两个返回点。
- 默认译文迁到 `runtime/src/main/resources/module-defaults/combat_stats.json`，235 条译文逐项保持一致，旧专用 en_us/zh_cn 资源移除。原始 237 条的导入报告未改写，两个未确认 ID 仍未猜测导入。
- 查找顺序改为模块配置 → 已注册实体当前语言译名 → 原方法结果。配置不分语言，命中即生效，允许用户手工添加新的标识；相同路径的不同命名空间共用一条映射。未知且未配置 ID 不会读取默认实体。
- `ModuleConfig` 严格检查平面 JSON、字符串值、重复键和尾随内容；解析完全成功才整体替换不可变快照。第一次用户文件损坏时使用内置默认值并报错，后续损坏保持上次有效快照，损坏文件不被覆盖。
- `ClientModules` 仅在客户端注册资源重载监听，各模块分别读取配置，一个模块出错不妨碍其他模块更新。
- 已补充中文注释及 `patch-mod/docs/modules.md`，说明新增模块步骤、两层注册、配置格式与当前单方法/VP 迁移工具的限制。
