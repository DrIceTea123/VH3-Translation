# 名称模块拆分实施：VTP 1.0.6

- 日期：2026-10-03（Asia/Shanghai）。
- 来源：用户明确要求将怪物名并入结算模块并扩展为怪物名称模块；宝箱/桶另建模块并提取相关 VP 规则；矿石与少量固定标签归 VP asm_main，补注释并按包名排序。
- 类型：实现、配置迁移、离线验证。状态：完成实现及双 JAR 导出；未做游戏验收、未构建安装包、未提交 Git。
- 关联：2026-10-02T04-59-03-vault-xp-module-5e8190ab；2026-10-02T05-12-00-name-module-reuse-79c2a681。后者是前期评估，以下为用户最终选择。

## 决定与实现

- 删除 vault_xp 的运行/转换模块、清单和配置；不新建 ore_names，不保留空模块。
- combat_stats 更名/扩展为 mob_names；结算 String 和经验 ResourceLocation 两个 formatter 共用实体路径词表，246 条 = 原 235 条 + 11 条基于实际实体 ID 的已知译文。12 条英文占位不强制覆盖实体语言表，缺项沿用已注册实体语言名/原文回退。历史 VP 输入文件随模块改名为 translations/vp/mob_names.json。
- 新 chest_names：10 方法、53 钩子。getter 与容器标题 BOTH；经验/预览、结算箱/桶/稀有度、图标稀有度、辅助功能七箱型 CLIENT。共用配置 53 条 = 33 条基础映射 + 20 条完整桶覆盖；完整键优先，未命中时组合已配置的稀有度与基础名，缺项保留原结果。稳定枚举 name 构造英文键，不读已汉化 getter 反推键，不改业务枚举。
- 从 VP main/long 的 6 组提取 61 对宝箱相关词条；混合组其他条目不动，原位留注释，旧片段保存 translations/vp/chest_names.json。通用迁移拒绝自动删除宝箱混合组；怪物自动迁移仅接受已审查的结算单方法组，新增 XP/多目标组要求人工审核。
- VP main 新增 20 对矿石和 4 对 handleDeltas 固定标签，按 client.data 排序。矿石使用 method=handleDeltas, local=MformatOreName，拦截完整调用结果。Ore Funsoide、Bonus 仍英文。
- 实查本地 VP 1.4.4+1：InsnNodeHandler 将替换调用插在 ARETURN 后；因此未采用 RformatOreName。MethodNodeHandler 的调用后注入经真实处理器离线测试验证。该原始 JAR 只作为测试依赖，不进入成品；没有声称已验证发布 VP 的游戏环境。
- 最终核对发现工作区 chest_names 的 20 个原英文桶占位已另行改为中文，保留现值，未回写英文。文档明确当前完整覆盖值及优先级。原 235 怪物项、52 个原中文箱/桶组合和非迁移 VP 规则均逐值核对一致。
- 新模块不接管 BountyHud 僵尸预览、GroupUtils 分组、玩家/皮肤/宠物外观、其他容器或装备稀有度；具体边界见 patch-mod/docs/chest-names.md 与 vault-xp.md。
