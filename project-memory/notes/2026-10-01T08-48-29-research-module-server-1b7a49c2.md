## 决定与实现

- 最新两端要求取代本轮早先“暂时仅客户端”的答复，也取代旧 STATE 中仅 forgeclient 的实现状态。客户端界面模块仍只在客户端启用；研究名支持客户端显示和服务端生成的通知。服务器配置修改后重启；客户端 F3+T，失败保留旧值；首次失败两端都阻止启动。
- 新增 research_names：外部配置 54 个唯一英文键，唯一正式文件为 program/基础+硬编码汉化/config/vh3_translation_patch/research_names.json。没有内置映射，新增条目只改 JSON。具体覆盖、原始文本与方法签名见 patch-mod/docs/research-names.md 和对应 properties，不在记忆重复维护。
- 研究名覆盖 8 类、11 方法、12 注入点：研究标题、悬浮名称、前置/互斥研究、操作与物品限制、知识精酿、卡组工作台和配方、研究解锁广播、登录研究替换通知。只在显示边界查表，研究业务 getter、存档、判定、解锁与同步标识保留原文。
- 两端通用运行模块登记到 CommonModules，客户端专属仍由 ClientModules 初始化，F3+T 包含两类；专用服务端只读取研究配置，不引用客户端 I18n。服务端消息使用服务端译文，客户端本地配置不会重译已经收到的文字。
- ASM 清单扩展多方法及 CLIENT/BOTH 适用端。共享 VerifiedMethodPatch 负责摘要、命中数、重复注入、副本替换和 ASM 分析；StringValuePatch 提供显示值和格式化回退钩子；两侧 ResearchNamesModule 保留专属定位、查表、导入和 VP 判定。
- VTP 改为 PRE_CLASS，先于 VP 的 CLASS 普通文案变换，避免把保留提示语误判成原方法摘要冲突。已实查本地 ModLauncher 9.1.3 的阶段顺序和可用 VP 1.4.4+1 的 targetClass 注册；完整环境指定 VP 1.4.4+3 的游戏共存仍待联测。
- VP 两组研究规则（60 对研究列表 + 1 对卡组）在原位置替换为说明注释，其他规则语义与排版保留。历史规则移入 translations/vp/research_names.json，供导入及冲突测试，不进入 JAR。当前 VP 分布已按用户调整后的实际文件重统计：main 624组/2862对，long 20组/1132对，complex 16组/328对，合计 660组/4322对。
- 版本由 1.0.3 一次递增为 1.0.4，双 JAR 已导出至工程 mods，旧版本对由既有导出流程清理。Git 忽略例外仍有效，新 JAR 可纳入 Git；本轮未自动暂存或提交。
