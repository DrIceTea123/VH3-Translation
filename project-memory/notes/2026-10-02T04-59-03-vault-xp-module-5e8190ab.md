## 实现与配置

- 新增两侧 VaultXpModule，模块 ID vault_xp，覆盖三个 formatter、handleDeltas 的四个固定显示标签及 createPreviewNotifications，共 5 方法、9 钩子，仅客户端启用。计算、统计、业务 ID、通知数值与寿命均保持上游逻辑。详细方法与键格式见 patch-mod/docs/vault-xp.md。
- 唯一正式配置 program/基础+硬编码汉化/config/vh3_translation_patch/vault_xp.json，共 354 条：72 箱/桶组合、20 矿石、258 怪物、4 固定标签；320 中文、34 英文占位。沿用现行 VP、combat_stats、OpenLoader 资源包及基线 vault_stats 的具体项；没有内置映射或运行时跨模块查表。条目和来源详情见模块文档。
- 默认使用完整英文显示名。矿石 ore_benitoite 对应 Ore Benitoite，不能套用物品英文名。宝箱因现行 VP 汉化 VaultChestType 显示字段，从未被改动的枚举 name 和桶标记构造稳定英文键；缺项仍回退原格式化结果，包括 VP 已产生的混合文本。
- VTP 先注入不意味着运行时看到原英文：PRE_CLASS/CLASS 是字节码变换顺序，实际 helper/getName 在游戏运行时才执行，已受其他类上的 VP 变换影响。新增测试模拟此情况。
- 复用严格外部配置、首次失败阻止启动、F3+T 失败保留旧值；重载只影响新通知/新建预览，不追溯改写缓存文字。专用服务端不读取 vault_xp。
- 新增共享 StringValuePatch.applyReturns，适配任意参数布局的 String 返回方法；VerifiedMethodPatch 支持声明额外栈空间。没有直接针对 Tracker 的现行 VP 规则，无需迁移；对新加入的该类 VP 规则保守报冲突，避免完整英文键被部分翻译。

## VaultChestType 评估（未授权实施迁移）

- 实查 VP 的类级规则有 9 对类型译文，匹配枚举 <clinit> 的标题式英文显示常量；getName 本身只有字段读取，不含这些常量。大写枚举业务标识不变。
- 扫描固定核心 7,903 个 class，getter 有 3 个直接调用点：结算页箱名、桶名、经验 formatter；均用于显示。name 字段只见构造器写入与 getter 读取。未声称覆盖其他模组或反射。
- 建议独立 chest_types 模块接管 getter 的 1 个返回点，9 个英文配置键，可采用 BOTH/CommonModules 保持 VP 两端作用范围；移除对应 VP 组并留说明、保存历史规则。该建议不是实施授权，本轮 VP 完全未改。详细评估见 patch-mod/docs/chest-types-assessment.md。
- 即便迁移，getter 仍返回中文，经验模块仍需稳定英文键；两个模块配置应保持独立。
