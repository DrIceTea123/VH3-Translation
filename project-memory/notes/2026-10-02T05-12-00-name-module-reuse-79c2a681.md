# 名称模块拆分复用评估

- 日期：2026-10-02 Asia/Shanghai
- 来源：本对话；用户要求评估将 vault_xp 怪物/宝箱/其他名称与已有 VTP、VP 合并，剩余可交 VP；补充若独有部分较多可保留 vault_xp 并说明复用关系
- 类型：用户偏好 / 实查结果 / 方案建议
- 状态：评估完成，未实施重构；没有修改 mod 源码、配置、版本和 JAR，没有提交 Git
- 关联：T-004、T-008；前一条 vault-xp-module note

核对当前配置，combat_stats 的 235 条与 vault_xp 对应显示键逐值完全一致，无冲突。vault_xp 总 354 条由 258 怪物、72 箱/桶组合、20 矿石、4 固定标签组成。怪物重复明确，宝箱是类型/稀有度/格式的结构复用，矿石主要来自资源包，不能将所有候选都算成相同键的重复表。

建议以 mob_names、chest_names、ore_names 为共享领域，四个 handleDeltas 固定标签交 VP，预览随宝箱模块。此为建议，用户没有要求立即实施。保留 vault_xp 的条件按其独有职责判断；若保留应作为适配层调用共享模块，仅保留独有配置，文档写清实际来源，避免两份映射同步。

已检查 VP 与真实字节码：宝箱除 VaultChestType 外还有 VaultChestTileEntity 的 4 对稀有度/32 对名称规则、结算桶后缀/稀有度、VaultChestIconElement、辅助功能枚举箱型片段。Strongbox 中文语序及 Treasure Chest 在实体方法省略稀有度等差异必须保留。getter 迁移建议现纳入更完整的 chest_names，不视为已授权新增 chest_types 和 chest_names 两套。

怪物候选有 BountyHud 的僵尸预览与 GroupUtils 具体实体显示分支。分组 Dweller/Horde、Bestiary 反向分类规则、宠物/装备外观名不能机械合并。FighterEntity 的 Vault Dweller 写入 lastName，后续还参与皮肤名字更新，不能与结算居民等级名强行共享。矿石结算从 ItemStack 已有语言名去掉 Ore/Vault Stone 片段，应区分完整名和短名，不重复复制资源包。

方案要求迁移用户配置并报告冲突、不让英文占位遮挡 I18n；收窄当前 Tracker 类级 VP 冲突检查；同一方法只能由一个模块认领；箱子通用入口兼顾服务端，客户端语言回退不得进入服务器。详细分析、来源候选、未决配置格式与实施顺序见 patch-mod/docs/name-modules-assessment.md。

本轮仅写评估文档和 note，前轮已完成的 1.0.5 与 72 测试结论未重新运行，游戏验证仍未完成。
