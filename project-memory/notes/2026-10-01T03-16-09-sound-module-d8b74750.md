## 实查与实现

- javap 确认 collectSoundEntries 反射读取 ModSounds 字段，通过 Field.getName() 传给 formatSoundName(String)。原始文本如 GRASSHOPPER_BRRR、RAFFLE_SFX、VAULT_AMBIENT_LOOP，是 Java 字段名，不是声音资源 ID 或格式化后的英文。
- 原方法按下划线拆分并生成首字母大写的显示名，对 sfx 特殊保留 SFX；有且仅有一个 ARETURN。
- SoundNamesModule 两侧独立注册。原方法唯一返回点插入 translate(原字段名, 原结果)，配置精确匹配大小写，缺少映射时保留原结果。不修改声音 ID、音量、播放与保存逻辑。
- 源码默认配置为 `patch-mod/runtime/src/main/resources/module-defaults/sound_names.json`；客户端首次生成 `config/vh3_translation_patch/sound_names.json`，共享现有严格 JSON 读取与错误保留有效快照机制。
- 203 条旧译文均与真实字段唯一匹配，全部保留。原始规则保存于 translations/vp/sound_names.json，导入报告保存于 translations/sound-name-import.json。
- 工程 asm_complex 原声音规则替换为 VTP 接管注释；标题、翻页等同类 6 条普通文案保持不变。
- combat_stats 的旧名称导入（包括原版实体集合）及 VP 规则识别从 PatchTool/VpCompatibility 移入早期模块类；运行侧名称处理原已在模块中，保持行为及 235 条配置不变。
- PatchModule 新增 ownsVpRule/importMappings 契约；公共 PatchTool 按模块 ID 分派 import-module，不硬编码结算导入逻辑。JsonFiles 共用离线文件读写，VpCompatibility 仅遍历和迁移，具体接管定位由模块决定。
- 声音模块同时识别 formatSoundName 直接规则和旧 collectSoundEntries/local=MformatSoundName 调用方规则，避免漏掉原 VP 冲突。
- 更新 README、模块开发说明和 VP 分类历史说明。当前 complex 为 36 组/735 对，统计须包含顶层 key/value 单条规则，不能只计算 pairs 数组。
