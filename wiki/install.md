# 安装与使用

当前汉化包 V2.7 面向 VH3 3.21.7。使用 Java 17 或更新版本运行安装器；先退出游戏并备份已有配置与存档。

## 安装器

1. 将安装器 JAR 与对应系统的启动脚本放在同一文件夹。Windows 双击 `windows系统点我启动.cmd`，macOS 双击 `macOS系统点我启动.command`，Linux 将 `Linux系统点我启动.sh` 作为程序运行。仍需 Java 17+，脚本会检查并提示。
2. 阅读并确认说明，选择整合包根目录。默认取 JAR 所在文件夹；所选目录应包含 `mods/`。
3. 安装器检查唯一核心文件、版本文件名和 SHA-256。不匹配时可返回选择；强制安装必须再次确认风险。
4. 基础内容始终安装。I18n 与 VP 保留“必装”标注并默认勾选，但可取消；取消仅跳过下载。JECh、Oculus 默认不选。
5. 校验内置内容后，依次清理 `vaultpatcher/cache/`、覆盖基础内容、下载选中模组、清理旧 VP/VTP。

启动文件与 JAR 放在一起即可，无需额外文件夹或配置。自动选择汉化包版本最高的安装器，版本相同再比较导出序列号：V2.10-1 高于 V2.9-99，V2.7-18 高于 V2.7-9。保留文件名末尾的 `-V汉化包版本-导出序列号.jar`；只有一个 JAR 时也可直接启动改名后的文件。macOS/Linux 若解压后无执行权限，可在解压目录运行 `sh ./macOS系统点我启动.command` 或 `sh ./Linux系统点我启动.sh`。也可以继续双击单独的 JAR，或使用 `java -jar "安装器文件名.jar"`。无图形桌面时，在对应启动命令末尾加 `--console`。

选中的模组若在 mods 中已有目标文件名，且 SHA-256 与 JAR 校验通过，会保留原文件并显示“跳过下载”。缺失、旧版或同名损坏文件仍下载；仅有其他文件名不会跳过。

**即使取消 VP，仍删除不符合配置目标版本的已知旧 VP 文件；保留目标文件 `vaultpatcher-all-1.5.3-fix.jar`。** 其他未勾选模组不下载，也不自动清理其旧版本；更新 i18n、JECh、Oculus 时应先处理重复旧版。旧文件清理按已知命名规则进行，自行改名的 JAR 需手动核实。

失败时安装器尝试还原本轮文件写入，已清 VP 缓存不恢复；若还原失败，会保留备份和 `backup/recovery.properties` 索引。断电或强杀不能保证自动还原。安装锁文件 `.vh3-installer.lock` 可保留，文件存在不等于安装正在运行。

## 手动安装及 VTP 升级

将 `translate-packs/` 的内容复制到目标根目录，另安装固定版本的 VP 和所需下载模组。VTP 从 1.0.16 起只安装一个 `vh3_translation_patch-<版本>.jar`；移除旧 runtime/transformer 双包及其他旧 VTP，不能混装。

单包内的运行模块自动提取到 `.vh3_translation_patch/runtime/<版本>-<SHA-256>/runtime.jar`。该缓存不放入 mods；损坏时从内嵌原件恢复。关闭游戏后可删除整个 VTP 缓存目录，下次启动会重建。

客户端与专用服务端使用相同安装器和 VTP JAR。客户端读取全部 14 份 VTP 配置；服务端读取 [模块表](vtp.md) 中的 8 个通用模块。服务端生成的消息使用服务端译表，客户端不能追溯重译已收到的文字。

## 更新翻译与排错

- VTP 配置在游戏的 `config/vh3_translation_patch/`，修改工程文件不会自动同步到游戏。客户端按 F3+T，重开声音、图鉴等缓存界面；服务端修改后重启。
- 首次缺失/损坏配置会阻止启动；重载失败保留该模块上次有效内容。词条未命中一般保留原文，怪物还会尝试实体语言译名。
- 更新 VP 后只清 `vaultpatcher/cache/`，不要删除含规则的整个 `vaultpatcher/`。旧 VTP 接管规则不得重新启用。
- VTP 会校验固定核心、目标方法、内嵌版本和 VP 冲突；失败时按日志修正文件组合，不可只改摘要绕过保护。
- 1.0.19 已在离线测试中修复图鉴详情返回时中文族类被当作资源 ID 的问题；仍需实际游戏确认。

回退时同时匹配补丁、配置和 VP 接管范围；回退至 1.0.15 及更早版本还须恢复对应双 JAR。安装器自检 `--check` 不安装、不下载。
